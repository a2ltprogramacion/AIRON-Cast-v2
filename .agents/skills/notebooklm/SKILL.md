# notebooklm
## Propósito
Regula estratégicamente el uso de la Base de Conocimiento interna transversal del Framework de Proyecto. Las directrices detallan específicamente cómo se extraen saberes previos (lecciones maduradas) y cómo cada eslabón nutre para un repositorio perdurable que ataca en frío.

## MCPs Disponibles Exclusivos
Todo requerimiento para extraer los hitos se reduce a:
`notebook_list` | `notebook_get` | `notebook_query` | `notebook_add_text`

## 1. Consulta Inicial (Precedente Técnico)
Previo a ejecutar comandos o abrir directrices sobre especulaciones, el analista o responsable evalúa `notebook_query` con foco en: **Patrones documentadamente asimilados y empaquetados exitosos, resoluciones a atranques de base arquitectónica y problemas comunes conocidos** en stacks idénticos implementados localmente en AIRON-Cast.

## 2. Inserción Estratégica
El archivo dictamina como de estricto cumplimiento para generar conocimiento imperecedero: **Cuándo y qué enviar a los registros profundos:**
La condición se restringe a enviar estrictamente a `notebooklm` **SOLAMENTE decisiones definitivas confirmadas** (soluciones puras halladas o implementadas respecto a cuellos de botella no triviales de integraciones que presentaban desafíos mayores).

## 3. Inserciones Proscritas o Vetadas
Toda inserción está rotundamente PROHIBIDA o sancionada si trata sobre emitir la finalización burda o regular rutinaria del ecosistema de tareas. El agente **no documenta tareas o pasos operativos resueltos y diarios (el "Día a Día")**. El registro es un banco histórico del conocimiento reutilizable para ahorros del equipo técnico, no es una bitácora temporal de ejecuciones triviales.

## 4. Estructura de Registro
Toda nueva ficha introducida debe moldear bajo esta directiva de base sin desviaciones sintácticas, invocando `notebook_add_text`:
- **Título Descriptivo:** Claro, identificable ante múltiples variables.
- **Contexto Operativo:** El ecosistema de base o causa/raíz que enmarcó el reto a enfrentar y generó la ficha técnica.
- **Decisión Tomada / Solución:** El mecanismo de despliegue que abatió exitosamente el issue (comandos precisos o flujos comprobados lógicamente de acción a emular u repetir).
